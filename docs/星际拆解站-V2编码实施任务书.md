# 星际拆解站 V2：编码实施任务书

依据：[V2 完整游戏策划案](./星际拆解站-V2完整游戏策划案.md)，版本 2.0-draft.1。

## 任务目标

将当前的线性六节点拼装游戏升级为“委托驱动、分支探索、装备构筑、基地经营”闭环。此次改版优先证明决策深度，不以更多卡片、按钮、资源或单纯美术升级替代玩法。

## 开始前

- 阅读当前仓库约定、完整策划与既有美术规范；确认当前分支和未提交改动。
- 原参考提交为 `0d92e49`，实际执行前检查漂移，不覆盖其他人的修复。
- 保留 V1 可运行入口和存档。采用独立 V2 规则版本与存档 key，不直接用新战斗处理旧航次。
- 建立需求—实现—验收表，逐项跟踪策划 AC01–AC22。

## 顺序任务清单

每次执行一个小任务，完成独立验证再继续；每三个任务做一次全流程集成检查并记录结果。以下均为计划，尚未实施。

| 任务 | 交付 | 独立验证 |
|---|---|---|
| T01 | V1 隔离、V2 状态定义、独立存档与来源字段 | 新旧存档互不覆盖，非法状态明确拒绝 |
| T02 | 一个标准运输委托＋3 层固定分支图＋燃料 | 目标可达、耗油正确、无油可返航 |
| T03 | 任务货/战利品暂存和交付结算 | 空间取舍实际发生，交付一次、取消无锁死 |
| 综合检查 A | 出航→探索→冲突→返航→刷新 | 闭环可玩且玩家知道自己在取舍什么 |
| T04 | 六层有向图生成与保底规则 | 1000 seed 的可达性、燃料和事件分布检查 |
| T05 | 救援、勘测委托 | 油耗/目标计数/取消/奖励互斥正确 |
| T06 | 废船、商人、异常区、求救信号 | 不可支付选项明确、无库存刷新或买卖套利 |
| 综合检查 B | 三类委托各走一趟 | 任务改变路线，非战斗事件有真实收益与代价 |
| T07 | 单位化同步战斗和统一预测器 | 同步交火、目标快照、过量伤害与日志一致 |
| T08 | 三套组合及普通设备数据 | 日程、邻接、上限、反击、机库重置正确 |
| T09 | 敌人类型和精英 | 至少两种配置对不同敌人有明确优劣交换 |
| 综合检查 C | 不同配置走相同 seed | 不用永久属性或随机隐藏伤害掩盖单一最优解 |
| T10 | 三舰船、船员、预算与预设 | 异形舱有效；缺件提示；免费配置可开局 |
| T11 | 库存、研究、普通蓝图与设施解锁 | 借用件无价值、研究唯一消耗、满库不丢件 |
| T12 | 安全返航/失败完整经济与旧档迁移 | 钱包、物品、委托和旧档账实一致，刷新幂等 |
| 综合检查 D | 连续两胜一败、一次研究、换预设 | 永久成长改变下一局；破产仍可出航 |
| T13 | 成品样板：船舱＋工作台＋事件＋返航 | 手机实际尺寸可操作，可辨识结构和状态 |
| T14 | 全量 V2 素材接入、三套打法表现、低动效 | 动效不改规则，不遮 HUD，来源与尺寸完整 |
| T15 | 五尺寸、键盘/触屏、可靠性与性能复验 | 对照 AC 与美术清单交截图、测量与日志 |

| T16 | 优良装备、经济和掉落调优 | 普通机制已成立后才启用品质；记录对照种子 |
| T17 | 真人试玩与问题修正 | 记录主动换计划/再开局，不能用自动化代替人类样本 |
| T18 | 发布说明、迁移与回滚、最终复验 | 清楚列已通过、待验证与未完成项 |

## 决策门槛

T03 后核心闭环不产生空间取舍，先修核心，不启动批量美术。T09 后一套配置明显全方面优于其他方案，先修装备—敌人的关系。真人试玩缺少条件时交付可玩的候选版本与测试方案，不能标成最终体验已验收。

## 必须遵守的实现约束

- 当前需求不要求新增框架或重写渲染器；复用 Phaser、TypeScript 与已有可靠模块。
- 玩法规则独立于渲染、音频、动画完成回调。预览与实战使用同一个确定性算法。
- 所有不可逆动作从统一入口检查只读权限、弹层状态、合法阶段和幂等 ID。
- 所有物品区分借用、自有、拾获、任务四种来源；禁止由“名字/颜色”推断来源。
- 不改变掉率来偷偷帮助玩家；教程与正式随机分离。
- 不删除历史报告或降低原有可靠性标准换取通过。需求变化记录在 V2 文档，不反向涂改 V1 历史。
- 各阶段提供可运行结果，不提交空按钮、假截图或只有配置未接入玩法的“完成”。

## 最终交付

可运行 V2、保留的 V1 入口/回滚路径、完整迁移验证、AC01–AC22 状态表、截图和运行日志、平衡模拟假设与结果、真人试玩记录或明确的待验证标记、已知限制、提交记录。

任务书仅规定实施与验收范围；是否合并主分支或发布到线上，遵循执行时用户授权和仓库流程。
