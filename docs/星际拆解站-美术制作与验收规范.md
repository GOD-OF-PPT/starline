# 星际拆解站：美术制作与验收规范

版本 v1.0 · 2026-11-21 · 对应《游戏策划与实施蓝图》v0.2

## 1. 适用范围与执行方式

本文件约束概念设计、图片生成、资产绘制、UI、动画、特效、资源导出和前端接入。用于统一后续制作，不代表已经完成美术资产或实机视觉验收。

- **必须**：影响玩法识别、风格统一或交付正确性的硬规则，未满足不能进入正式资产库。
- **目标**：首版质量和性能预算，需通过真机验证；调整时同步修改规范并记录原因。
- **可选**：预算允许时添加的表现，不得挤占关键规则与信息。
- 玩法数值、设备效果和内容范围由策划主文档决定；本文件不新增设备、品质、付费功能或玩法。
- 本文件是美术细节的统一依据。修改主色、视角、格子尺度或品质表达时，必须同步资产模板与主文档，不能在单个素材里自行变化。

## 2. 美术总方向

**一句话：一座能被修好、能逐渐做大、具有机械实感的微缩太空拆解站。**

五个关键词：机械结构、紧凑轮廓、使用痕迹、温暖工作灯、清晰功能。

### 要做到

- 大形有重量，边缘有倒角，结构看得懂；物件看起来能制造、能拆卸、能修理。
- 精细主要来自轮廓、材质、层次和运动逻辑；缩到手机实际尺寸仍然清楚。
- 基地整体安静、有生活气息，出航时节奏更紧；两者使用同一套材料和技术语言。
- 破旧有具体原因：掉漆、替换面板、焊接补丁、局部积尘；修复后出现完整部件、亮灯和工作活动。

### 禁止出现

- 糖果色大面积铺陈、装饰花边、拟人卖萌的机器表情、无功能的可爱挂饰。
- 整屏霓虹、所有边缘都发光、每件普通货物都像传奇装备。
- 大面积漆黑导致看不清；满屏锈蚀、划痕和高频噪点导致物品混成一团。
- 像素风、写实照片、扁平卡通、光滑塑料 3D 混用。
- 借用其他游戏的可识别角色、徽记、UI 皮肤或整套造型。

这里锁定题材与视觉偏好，不以性别替代具体设计标准。

## 3. 视角、构图与光照

| 场景 | 投影与构图 | 统一规则 |
|---|---|---|
| 基地 | 2D 轴测，地面菱形宽高比 2:1，无透视消失点 | 两条地面轴投影斜率为 ±1/2，竖直结构保持竖直；全部建筑使用同一模板 |
| 船舱拼装 | 正交俯视，方格不倾斜 | 图片轮廓对应占格，禁止使用基地轴测角度替代 |
| 战斗 | 正交侧视，玩家在左、敌人在右 | 炮口、护盾、命中位置清楚；镜头不自由旋转 |
| 物品图鉴 | 沿用船舱俯视资产，另附说明 | 不额外生成一个比例和结构不一致的“展示版” |

所谓“等距风格”在本项目具体执行为上述 2:1 轴测规则，不混入另一套严格等距投影。

**基地与战斗光照必须一致：** 主光从画面左上照入，朝右下投影；暖色工作灯作为局部补光；背光面仍保留结构。场景光不能使未损坏设备看起来像报警状态。

**船舱资产采用柔和顶光。** 可旋转物品不烘焙强烈的方向性投影；接触阴影由渲染层独立绘制，方向固定在屏幕右下。禁止直接旋转一张带强左上光、长阴影的图片，造成光源跟着设备转动。

基地每屏最多一个高细节视觉中心；其他建筑和星空降低对比度。工作机器人与装饰不得遮住建筑选择点。

## 4. 配色、明暗与视觉语义

### 固定基础色板

| Token | 色值 | 用途 |
|---|---|---|
| `bg-space` | `#111A29` | 太空与页面底色 |
| `surface-panel` | `#1C293A` | 信息面板底色 |
| `surface-raised` | `#26364A` | 按钮次级底色、悬浮区域 |
| `material-steel` | `#566477` | 钢材中间色；不能直接作为重要文字颜色 |
| `text-primary` | `#E9EDF2` | 标题、数值、主要说明 |
| `text-secondary` | `#AFBDCD` | 次要说明、单位、辅助标签 |
| `accent-action` | `#F6B852` | 主要行动、工作灯、确认焦点 |
| `accent-energy` | `#62D6DF` | 能量传递、护盾、有效连接 |
| `state-danger` | `#F27564` | 危险、非法放置、耐久损伤 |
| `text-on-accent` | `#111A29` | 琥珀实心按钮上的文字 |

**颜色使用规则：**

- 以中性冷色构成大面积画面，暖色集中在操作焦点与工作区域。初始构图目标约 75% 中性、20%次级材质、5%强调色；这是构图指导，不是逐像素配额。
- 普通文字目标对比度 ≥4.5:1；必要图标、格子边界与焦点标记目标 ≥3:1。装饰不承担功能信息时无需强行提亮。
- 上述纯色组合已计算：主文字/面板约 12.51:1，次文字/面板约 7.69:1，危险色/面板约 5.26:1，深色字/琥珀按钮约 9.88:1。
- 浅色字/琥珀按钮仅约 1.50:1，钢灰/面板仅约 2.44:1，因此禁止使用这两种搭配呈现重要文字。
- 这些结果只适用于给定的实色组合；叠加透明、纹理、模糊、渐变后必须重新检查最终画面。
- 危险有红色，也必须有文字或图形；有效连接有青色，也必须有连线和增益数值。灰度下仍能理解状态。
- 同一屏不要让货币、稀有度、危险、主要按钮都争用同一种金色发光效果。

## 5. 造型、轮廓与材质规则

### 造型语言

1. 每件物品由一个主要体块、一个功能特征、少量次级结构构成。先读出“炮/电池/盾/维修”，再看划痕。
2. 设备以倒角矩形、圆柱、护板为主，组合有限形状形成一致的制造语言。
3. 配件有连接关系：炮管连炮座、电芯有接线口、无人机有工具臂。不能靠随机管线堆砌“科幻感”。
4. 装饰不得与可连接接口混淆。电池增益是正交邻接规则，接口图形不能暗示只有特定方向才生效。

### 设备识别表

| 设备 | 第一识别特征 | 第二识别特征 | 禁止误导 |
|---|---|---|---|
| 激光炮 | 长炮管与短炮座形成方向感 | 炮口开孔、后部散热片 | 朝向只用于摆放形状，不暗示实际射界或额外射程 |
| 电池 | 紧凑方形壳体与圆柱电芯 | 两侧接线件与能量窗 | 不画成金币、宝箱或可拾取治疗包 |
| 护盾板 | 宽护板或层叠装甲轮廓 | 中央场发生器 | 不与普通货物合金条使用相同轮廓 |
| 维修无人机 | 明确的 L 形外轮廓 | 机械工具臂与维修标记 | L 形缺口保持透明，不画成完整方块 |

### 货物识别表

数据盒是短厚盒体；合金条是成组长条；冷却罐是细长容器；旧引擎是厚重方形机组；折叠天线保留 L 形缺口；古代导航仪保留 T 形轮廓和独特环形核心。货物不用武器准星或护盾徽记。

### 材质

- 涂装金属：大面积哑光，受力边缘局部露出底材。
- 裸金属：高光窄而有方向，不能涂成镜面铬。
- 橡胶/软管：偏暗低反光，不能抢主体轮廓。
- 玻璃/能量窗：面积小、透光适度，不用整件物品的泛光代替材质。
- 使用痕迹目标覆盖可见面积的 10%–20%，集中在边缘、接缝与维护位置；普通损耗不等于战斗损坏。
- 缩小后消失的铆钉和字样不是必要细节。重要结构在实际尺寸下至少保持约 2 CSS px 宽。

## 6. 船舱占格与素材尺寸合同

### 网格尺度

- 船舱逻辑固定 4×4。棋盘显示宽度为 `min(可用内容宽度, 384 CSS px)`，单格边长等于棋盘宽度除以 4。
- 页面左右基础留白 16 CSS px；360px 宽屏下棋盘宽 328px、单格 82px。390px 宽屏下棋盘宽 358px、单格 89.5px。
- 网格线画在格内，不额外插入布局间距，避免多格物品的尺寸与格子坐标不一致。
- 高度不足时先收起中部场景和非关键说明，再允许次级内容滚动；船舱和底部确认操作不得互相覆盖。

### 物品素材

统一每逻辑格 192×192 源像素，覆盖最大 96 CSS px 格子的 2 倍清晰度。这里的“2 倍”是源文件真实绘制分辨率，不是把模糊小图放大。

| 形状 | 默认导出画布 | 占格掩码 |
|---|---|---|
| 1×1 | 192×192 px | `[[0,0]]` |
| 1×2（竖向） | 192×384 px | `[[0,0],[0,1]]` |
| 1×3（竖向） | 192×576 px | `[[0,0],[0,1],[0,2]]` |
| 2×2 | 384×384 px | `[[0,0],[1,0],[0,1],[1,1]]` |
| L 形 3 格 | 384×384 px | `[[0,0],[0,1],[1,1]]` |
| T 形 4 格 | 576×384 px | `[[0,0],[1,0],[2,0],[1,1]]` |

坐标 x 向右、y 向下；所有形状旋转后平移至最小 x、y 均为零。美术与规则共用同一份形状配置，不分别维护两套。

**必须：**

- 实体可见像素只进入占格掩码覆盖的区域，L/T 形缺口保持透明；阴影与光效独立，不参与命中检测。
- 外轮廓距占格外边缘留约 12 源像素，内部跨格连接处不留断缝。该留白不改变逻辑占格。
- 船舱资产不包含固定投影、品质边框、数字、名称、价格、选择状态、格子底板；这些由程序绘制。
- 在图集中裁透明边时，保留原始尺寸和裁切偏移；排布按逻辑画布计算，不能以裁切后图片宽高计算。
- 绘制坐标锚点使用规范化包围盒左上角；旋转围绕几何中心后重新规范化，禁止以裁切后图片中心代替。
- 货物/设备旋转时，名称、数值、品质标记保持屏幕正向；命中区域使用格子掩码，不使用透明图片包围盒。

### 其他素材建议规格

| 类别 | 源文件目标 | 导出原则 |
|---|---|---|
| 基地整体概念图 | 1536×1536 px 或更高的分层源稿 | 只用于定稿参照；正式画面拆层，不导出一张带 UI 的背景 |
| 基地可交互建筑 | 按最高实际显示宽高的 2 倍 | 单纹理边长目标 ≤2048；锚点为地面占地中心 |
| 侧视舰船 | 768×384 px 统一画布 | 主体长度约占画布宽度 75%；炮口、命中点、引擎点用归一化坐标记录 |
| UI 图标 | SVG 源文件，24px 基准网格 | 简单符号用矢量；位图备用导出 48px 与 72px |
| 特效帧 | 常用 128×128 或 256×256 px | 同组帧尺寸、锚点、时序一致；大爆炸单独预算 |

超过预算先调整构图、拆层和展示尺寸，再扩大纹理。按需加载不能替代单张纹理尺寸检查。

## 7. 品质、价值与状态：不得混用

首版只有“普通、优良”两个品质，不出现紫、橙、红多档稀有度。

| 信息 | 表达 | 规则 |
|---|---|---|
| 普通品质 | 单段品质刻线＋“普通”标签 | 低强调，不持续发光 |
| 优良品质 | 双段品质刻线＋“优良”标签，增加一个功能部件细节 | 不扩大占格，不改变识别轮廓，不借品质暗示不存在的技能 |
| 高价值货物 | 明确报价和每格价值，可用货币符号 | 高价不自动等于高品质或强战力 |
| 选中 | 琥珀色角标/轮廓＋物品说明 | 只作用于当前对象，避免所有物品常亮 |
| 合法落点 | 青色占格轮廓＋勾号 | 精确展示所有占用格，不只标鼠标所在格 |
| 非法落点 | 红色冲突格＋叉号＋简短原因 | 原因区分越界、重叠、当前状态禁止操作 |
| 邻接生效 | 短连接线＋对应炮的增益值 | 同一炮仅显示最终有效加成，不画成多块电池叠加 |
| 加成达到上限 | 数值旁显示“已达上限” | 不继续用特效暗示实际仍有增益 |
| 借用设备 | 固定借用标记，说明不可出售 | 不把回收价显示成可兑现的正常收益 |

优良品质的区别同时依赖结构细节、刻线和文字。颜色可以辅助，但不能成为唯一依据。

## 8. UI、字体与信息层级

> v1.1 修订（2026-11-24）：同步《体验重铸》§4.3 / A09，正式确立「**舰载工业终端**」UI 视觉标准，废止旧版圆角面板/胶囊条款。

### 字体、间距与工业终端几何

- 游戏内中文使用清晰的无衬线黑体；优先可用系统字体或已确认许可的字体。全项目保持同一字体策略，不混入三种以上字形风格。
- 默认信息 14–16 CSS px；主要数值 20–24px；页面标题 22–28px；次要标注至少 12px。
- 关键危险提示、预计损失和按钮不使用最小字号。正文行高 1.4–1.6；数字开启等宽数字特性（`font-variant-numeric: tabular-nums`），重要读数叠加技术感等宽字体回退栈。
- 使用 4px 间距尺度：4、8、12、16、24、32。
- **钢制机箱框与 45° 切角**：主面板、弹层与核心卡片采用舰载工业终端钢框语言，统一使用 45° 切角（`clip-path` 6–14px 切角或 0–2px 机加工硬倒角）、四角铆钉细节、冷色顶边高光与暗色内凹倒角；禁止使用通用 SaaS 风格的 8px/12px/16px 大圆角卡片。需保留外溢挂件或 `overflow: visible` 的容器（如残骸夹具热区、星图遗物角标节点、船舱棋盘外框、主舞台容器）采用 2px 硬倒角钢框，避免 `clip-path` 误裁子元素。
- **CRT 内凹屏信息区**：耐久/燃料/信用点读数、战力推演抽屉、货舱统计条、结算账单与战报条采用深色内凹 CRT 屏样式，叠加 4–6% 低干扰水平扫描线纹理、荧光青/琥珀高亮与等宽数字。
- **功能性胶囊 pill 归零**：禁止在 V2/V3 界面及弹层中使用 `border-radius: 999px/99px` 的功能性胶囊标签、按钮、进度条或计数徽章，统一改为 45° 切角工业铭牌、刻度凹槽进度条或 2px 方正计数牌；仅允许 `≤ 10px` 的纯装饰性圆形状态指示灯（LED）保留圆形。
- 按钮可点击区域至少 44×44 CSS px；可视图标小于该尺寸时扩展命中区域。
- 文本必须可编辑、可本地化，不烘焙进图片；不通过缩小字号解决长文案，改用换行或重新排版。

### 画面信息优先级

1. 当前决定需要的信息：耐久、下一战预计损失、奖励属性与尺寸、返航收益。
2. 正在操作的物品：轮廓、占格、连接效果。
3. 舰船与战斗表现。
4. 氛围背景、星空、装饰活动。

背景星点不能看起来像可收集物；战斗飘字不遮住长期状态。重要数字底下使用稳定实色底板，不直接压在运动纹理上。

### 控件状态

- **实体机械按键**：按钮至少有正常、悬停/聚焦、按下、断电禁用四种状态；具备底部物理厚度边（3px 实体立边）、悬停冷高光、按下下沉位移（`translateY(2px)`）与内嵌高对比可见焦点框（`:focus-visible` 不被 `clip-path` 裁切），移动端保持 ≥44×44 CSS px 触控热区且不依赖悬停查看说明。
- **危险与警示**：危险/致命/不可逆销毁操作（如舍弃、重置存档、致命切割、高危航路）叠加斜向警示斑马条与加粗/双线安全框，同时确保文字区高对比可读；预计下一战必败时突出危险说明，允许主动返航，不使用连续闪烁诱导继续。
- **断电禁用态与灰度可读性**：禁用与未解锁控件表现为“断电冷金属”（暗沉无光底面、取消立体底边、虚线冷灰槽框、低饱和度但仍可读的金属灰字），禁止仅靠降低 `opacity` 处理，并在附近给出禁用原因。在纯灰度/色觉障碍视图下，正常、选中、联动、警示、危险、断电六类状态须依靠边框线型（实线/虚线/双线/左加粗警戒边）、切角/斑马纹轮廓、亮度梯度与符号文案独立区分。
- **低动效兼容**：同时响应 `body.reduced-motion` 与 `@media (prefers-reduced-motion: reduce)`，关闭动态扫描线、脉冲与位移过渡而不损失任何静态状态信息。

返航与继续必须同时可见、文案清楚、命中区域相当。暂存区未处理完时显示“先整理奖励”，并定位未处理物品。

拖动时将物品预览适当抬到手指上方，原位置保留轻量轮廓。点选放置路径始终可用；选择、旋转、取消按钮不依赖精细手势。

## 9. 场景分层与成长表现

### 基地制作层

按从后到前组织：星空远景 → 远处结构 → 平台地面 → 建筑主体 → 可移动舰船与机器人 → 前景管线/扶手 → 局部特效 → 可交互标记 → DOM 界面。

建筑遮挡顺序依据地面锚点，而非图片左上角。交互标记属于 UI 层，不能被建筑图遮住。非必要前景在覆盖操作区域时降低透明度或隐藏。

### 建筑成长必须是结构变化

| 建筑 | 破旧状态 | 修复/启用状态 |
|---|---|---|
| 工作台 | 断电、缺工具、机械臂折叠 | 面板完整、灯亮、机械臂工作、工具上墙 |
| 船坞 | 封闭泊位、损坏导轨 | 泊位展开、引导灯点亮、第二舰船可见 |
| 收藏展台 | 封存底座、保护布 | 完整玻璃罩、藏品实体、定向展示灯 |

破旧与修复版使用相同画布、地面锚点与占地范围，替换不能让建筑跳动。施工火花和进度反馈为独立动画层，不为每一帧重复绘制整栋建筑。

“未解锁”“资金不足”等状态是交互状态，不等于建筑损坏；在 UI 中解释条件，不通过把整栋建筑涂黑代替。未实装的通讯塔和第二区域不制作成可点击入口。

## 10. 动效、特效与反馈等级

### 统一运动语言

- 设备运动短促、有重量；面板移动平稳；机械臂绕真实关节旋转。
- 常规按钮反馈目标 ≤100ms；物品吸附 100–150ms；连接反馈 150–250ms；奖励展示 300–450ms。
- 放置最多一次轻微压缩回弹，缩放变化目标不超过 4%；禁止每个控件持续呼吸或弹跳。
- 常规 UI 使用缓出；机械动作允许短暂启动和停靠，不使用同一弹簧效果覆盖所有对象。
- 帧动画建议 12–16fps 表现机械动作，位置与 UI 插值按真实时间计算；逻辑不依赖动画帧数。

### 反馈分级

| 等级 | 事件 | 表现上限 |
|---|---|---|
| 1 | 普通选择、旋转 | 控件状态、轻音效；无震屏 |
| 2 | 放置成功、邻接生效 | 局部轮廓、一次脉冲、数值变化 |
| 3 | 高价值奖励、险胜 | 局部展示、短音阶；主场景轻微震动可选 |
| 4 | 满载返航、首次建设完成 | 场景变化、卸货/施工表现；可跳过 |

不得在普通货物上套用最高等级庆祝。强度应对应事件，而非随机叠加。

### 特效限制

- 不用全屏白闪，危险不用全屏红闪；警告采用常亮标签和局部边缘提示。
- 可选震屏仅作用于战斗世界层，位移目标 ≤3 CSS px、持续 ≤120ms；HUD、船舱与按钮不震动。
- 光效不得遮住物品外轮廓、剩余耐久和主要按钮。不同特效同时发生时，优先保留伤害与状态信息。
- 常规单次爆发目标 ≤24 粒子，同屏活跃粒子目标 ≤100；低画质关闭装饰粒子，保留命中和结果提示。
- 2 倍战斗速度改变表现节奏，不改变结果；同一伤害事件不得因补间完成回调而重复扣血。
- 低动效模式取消震屏、漂浮与闪烁，连接改为静态线条，保留必要结果；粒子关闭不能影响胜负判断。

音画配合沿用主文档的短音效预算。看不到声音、关闭声音或跳过动画时，都必须读到同样的关键结果。

## 11. 源文件、命名、导出与接入

### 文件与资产身份

采用英文小写下划线：`类别_对象_视图_品质或状态_动作_版本`。

示例：`eq_laser_top_common_idle_v001.png`、`eq_laser_top_improved_idle_v001.png`、`bld_workbench_iso_repaired_idle_v001.png`。

运行时使用稳定键，例如 `equipment.laser.common`；文件名版本不能成为业务逻辑中的物品 ID。禁止在代码里通过中文文件名或颜色猜测设备类型。

### 每件资产的交付信息

- 可编辑源文件、透明底导出文件、真实尺寸预览。
- 唯一 ID、用途、视图、状态/品质、源尺寸、原始画布、裁切偏移、锚点。
- 格子掩码或世界占地范围；舰船的炮口、引擎与命中挂点。
- 动画帧范围、帧率、是否循环、事件对应关系。
- 作者/工具、来源、许可、版本、修改说明。生成素材还需保存提示词与参考图来源。

### 导出规则

- 位图统一 sRGB；透明物件保留正确 Alpha，不带白底、棋盘底、黑色毛边或外部投影。
- 源稿优先保留无损格式；运行时静态资源可按质量与透明需求选择 PNG 或 WebP。所有压缩都在最终尺寸检查轮廓。
- UI 简单图标优先 SVG，禁止在 SVG 中嵌入一张低清位图冒充矢量。
- 设备/货物图集禁止自动旋转打包，降低旋转交互的坐标歧义；图集边缘挤出 2px、条目间至少留 4px，防止采样串色。
- 不导出整屏带按钮和文字的背景来替代 UI。场景底图、物品、控件、文字各自独立。
- 透明留白不等于“尺寸够大”：检查实体有效像素，避免 1024px 画布里只有 100px 物件。

## 12. 包体与运行预算

继承主文档：首屏压缩后资源 ≤5MB、首版总资源 ≤15MB，均为目标。优先加载当前场景；进入基地后再预载下一场景资源。

建议首屏预算分配：应用逻辑与引擎 ≤1.5MB、首屏图像 ≤2.5MB、首屏音频 ≤0.5MB、字体/配置/余量 ≤0.5MB。若实测分配不适用，可调整子预算，但须保持总预算并记录网络瀑布图。

纹理内存与下载体积分别核算：RGBA 2048×2048 单张约占 16MiB，不含 mipmap。正常场景常驻解码纹理目标 ≤64MiB、场景切换峰值目标 ≤96MiB；生成 mipmap 和引擎额外副本要计入实测。

优先按场景拆图集、复用状态层、限制粒子和阴影，避免一次载入全部建筑状态。单纹理目标 ≤2048px，接入时查询运行环境实际纹理限制并验证回退策略。性能降级不能降低文字与占格边界的可读性。

## 13. AI 辅助制作规则与提示词模板

如果后续使用图片生成，先确定母版，再生产同族资产。不得把独立随机生成的图直接拼成正式界面。

### 先做一个可复用样板组

工作台破旧/修复两状态、玩家船侧视、四种普通设备俯视、一个奖励弹层布局。把它们放进同一张实际尺寸的手机界面里检查，再冻结颜色、轮廓、材质与比例。

首张母版不通过时不批量生成。若需要用户审美选择，提供可比较的少量具体样稿；没有外部反馈时，按本规范完成内部审查并记录风格版本，不凭空增加审批阻塞。

### 可复用提示词骨架

> 为原创游戏《星际拆解站》制作【资产名称】。遵循所附已确认母版的造型、材料与色板。风格为精致微缩工业科幻，哑光涂装金属、合理机械连接、局部使用痕迹，缩小后轮廓清楚。【视图：基地 2:1 轴测 / 船舱正交俯视 / 舰船正交侧视，三选一】。【功能识别特征】必须明显。【画布尺寸】；【占格掩码/占地范围】；主体完整，规定缺口透明。船舱物品柔和顶光、无投射阴影；基地与舰船使用左上主光。交付不含文字、数字、价格、品质边框、按钮、水印和背景装饰的独立资产。

> 排除：混合视角、写实照片、像素风、糖果塑料感、全轮廓霓虹、过密随机机械线、错误占格、透明缺口被填满、裁切主体、伪透明棋盘底。

模板中的变量只供制作时填入，不允许作为未完成占位内容交付。图片生成无法保证精确掩码、透明度和尺寸；必须经过抠图、结构修正、画布归一化与格子叠加检查。优良品质优先在普通母版上编辑，不能重新生成一个完全不同的设备。

## 14. 制作顺序与质量门槛

1. **风格母版：** 完成一个样板组，确认三种视图协调；先看实际尺寸，再看放大细节。
2. **功能样板：** 四种普通设备接入真实船舱，验证掩码、旋转、点选、邻接、品质标签位置。
3. **一屏完成度：** 完成一张可操作的整理界面和一张基地界面，检查布局、光照、文字、对比度；不是仅提交静态效果图。
4. **批量制作：** 按相同模板完成优良设备、货物、建筑状态和舰船。
5. **反馈与性能：** 接入动效、音效、低画质/低动效；在目标设备检查帧率和内存。
6. **交付封版：** 更新 manifest、来源记录、版本与截图；通过以下验收后才将资产状态改为正式。

本轮只补充标准，以上阶段是后续执行计划，尚未声称任何阶段已完成。

## 15. 美术验收清单

### 单资产检查

- [ ] 缩到实际格子大小，能区分炮、电池、盾、维修无人机，不依赖名称或颜色。
- [ ] 轮廓符合占格；L/T 缺口透明；旋转四次回到原图，不漂移、不错位。
- [ ] 明暗和材质符合对应视图；旋转不会带着投影光源转动。
- [ ] 普通/优良保留同一主体身份，有清楚且不过度的品质差异。
- [ ] 无白边、黑边、伪透明、文字残影、裁切缺件或缩放模糊。
- [ ] 锚点、原画布、裁切偏移、挂点、版本与来源完整。

### 组合画面检查

- [ ] 360×640、390×844、430×932 CSS px 竖屏，以及 844×390 横屏和 1366×768 桌面均检查；设备安全区另行覆盖。
- [ ] 在 360px 宽屏，玩家能直接读到耐久、预计伤害、奖励尺寸和返航收益。
- [ ] 将实际屏幕截成灰度后，品质、危险、选择和合法/非法落点仍可分辨。
- [ ] 在最复杂战斗与特效同时出现时，关键状态没有被遮挡，文字对比仍达内部目标。
- [ ] 手指拖动物品不会完全盖住落点；点选操作可完成同一任务。
- [ ] 基地升级前后至少出现结构、灯光、工作活动中的两项改变，且无跳位。
- [ ] 无假按钮、未实装入口、模板水印、无关装饰卡片或不一致图标。

### 运行与交付检查

- [ ] 场景切换、2 倍速、刷新恢复不会错播品质、掉落或胜负特效。
- [ ] 静音、低动效、低画质仍保留所有决策信息。
- [ ] 首屏、总包体、纹理尺寸和内存有实际测量；性能记录注明设备、系统、浏览器、分辨率与画质。
- [ ] 图集边缘不串色；缩放和旋转后无接缝；高像素密度屏幕文字清楚。
- [ ] 所有运行资产都有源文件或可复现生成记录、许可说明、稳定键和版本。

### 缺陷处理

阻断级：误导占格/战力/收益、关键文字不可读、按钮不可操作、资产缺失、资源导致无法运行。修复前不得交付。

主要级：混合视角、设备难以区分、品质失真、重复错位、重要动效遮挡操作、明显不符合整体风格。正式美术封版前必须修复。

次要级：不影响识别的局部瑕疵、轻微纹理问题、可选装饰不足。记录位置与截图，按优先级处理，不以增加细节替代前两级修复。

最终验收必须基于实际可操作页面、实际展示尺寸与目标设备表现；单张高分辨率海报不能代替游戏美术验收。
